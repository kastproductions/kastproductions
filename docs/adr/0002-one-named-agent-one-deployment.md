# One named agent is one deployment

A client who buys a standing agent buys one deployment addressed by one name. A second differently named agent is a second build and a second monthly line, even when the two agents talk to each other.

eve documents two ways to reach several agents, and we price the documented one: separate deployments called as remote subagents. Mounting two differently named chat apps inside a single deployment looks possible, because the channel id is the file stem, the webhook route is overridable and credentials are per channel, but no eve document walks that end to end and every published template mounts exactly one chat channel.

## Consequences

Subagents are unaffected. A Department tier agent runs five specialists behind one name, which is a different thing from five names.

The rule also settles the scope question that otherwise arrives just after a fixed price is agreed, when someone asks whether the agent can answer as `@finance` too.
