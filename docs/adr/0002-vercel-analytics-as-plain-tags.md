# Vercel Web Analytics as plain tags, rendered on every build

Production measured nothing for months because the tracker was rendered behind a build-time condition, so the site now writes the two tags Vercel documents for plain HTML into every page, unconditionally, pointing at the first-party path only a Vercel deployment serves. We do not use the `@vercel/analytics` component: it appends the tracker from an effect, which leaves the tag out of the built HTML, adds a dependency and a client chunk for what two static tags do, and puts the wiring beyond the export seam ADR-0001 relies on. The cost is lock-in and reach: another host loses analytics, and an ad blocker that blocks the first-party path drops the visit, because the per-deployment path that avoids that needs the package and its build-time seed; README's Analytics section carries the operating detail.
