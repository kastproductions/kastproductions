# Graph keys keep the trailing slash, addresses follow the canonical

The schema.org graph spells the site URL two ways on purpose: a canonical tag names one address, and this site names the home page as `https://www.kastproductions.com` with no trailing slash, so every `url` in the graph follows `pageUrl` and spells it that way. An `@id` is a key, not an address, two spellings of one key are two entities to whoever reads the graph, and the site-wide keys were published as `https://www.kastproductions.com/#organization` before the pages had records, so every key goes through `nodeId` and keeps the slash after the host. One spelling everywhere meant either re-keying nodes a crawler already holds or changing the canonical every page states, and both cost more than a two-spelling rule that one function and `tests/page-graph.test.ts` hold.
